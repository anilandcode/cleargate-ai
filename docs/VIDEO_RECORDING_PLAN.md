# ClearGate AI Video Recording Plan

## Recording Setup

- Use a desktop viewport around 1440 x 1000.
- Open the deployed Vercel URL in an incognito window.
- Clear local storage before the final take.
- Keep browser zoom at 100%.
- Verify configured live integrations immediately before recording.

## Five-Minute Timeline

### 0:00-0:35 - Shadow AI Problem

Show the populated Inbox. Explain that employees adopt AI tools before formal review and that the queue ranks exposure, risk, evidence freshness, and decision.

### 0:35-1:10 - Seeded Judge Workspace

Point out 11 tools and mixed outcomes. State that seeded data is visibly labeled and exists to make the demo reliable.

### 1:10-2:35 - Highest-Risk Review

Open Otter.ai. Explain call-recording exposure and the blocked pending review decision. Click **Run live verification**.

### 2:35-3:35 - Evidence Provenance And Policy

Open a final evidence row. Show official URL, retrieval product, origin, fetched timestamp, excerpt, SHA-256, extraction method, policy mapping, and human-review indicator. Open Policy Gate and show deterministic reasoning.

### 3:35-4:15 - AI Vendor Passport

Open Memo and export the memo. State that the output is designed for procurement, GRC, and audit handoff.

### 4:15-4:40 - Optional Verified Action

Only if verified immediately before recording:

- show `AI-extracted finding` from a real AI/ML API response;
- send an escalation and show `Sent to Slack`;
- show Scraping Browser only if a real evidence row says `Scraping Browser`;
- mention evidence drift only after two live reviews produce a real hash change.

Otherwise, state that these are implemented optional paths and show the draft-only workflow fallback.

### 4:40-5:00 - Enterprise Value

Close with the buyer, the operational value, and the distinction between current implementation and roadmap.

## Recording Safety

- Never show Vercel environment variables, Bright Data tokens, AI/ML API keys, Browser API credentials, or Slack webhook URLs.
- Do not claim a live partner call unless the UI confirms the successful server-returned record.
- Keep a fallback take using seeded data in case external credentials or vendor pages fail.
